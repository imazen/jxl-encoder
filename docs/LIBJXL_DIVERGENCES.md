# libjxl Divergences — Authoritative Table

**Purpose**: Every gate, tolerance, constant, or algorithmic choice where this encoder differs from libjxl reference. Maintained per-chunk; mandatory updates with every code change that creates/changes/removes a divergence.

**Future direction**: A refactor of the gate/strategy plumbing is proposed in [`docs/RFC-strategy-refactor-2026-05-22.md`](RFC-strategy-refactor-2026-05-22.md) (W44-190). **W44-192 (2026-05-22) shipped Phase 1** of the recommended Solution B: the [`jxl_encoder_macros::strategy_def!`](STRATEGY_DEF_MACRO.md) proc-macro + a 3-gate prototype validation. **W44-193 (2026-05-22) shipped Phase 2** — the production big-bang migration: all 24 production gates from `api.rs` are now generated by a single `strategy_def!{}` invocation in [`jxl-encoder/src/gate_registry.rs`](../jxl-encoder/src/gate_registry.rs) (the hand-written `EncoderImprovementsCustom` struct + `ResolvedImprovements` struct + 5 hand-written `impl` constructors + `apply_env_var_fallbacks` are gone — ~890 LOC net deleted). Each gate declaration in the macro carries `divergence_section` + `divergence_row_ref` metadata emitted as compile-time consts (`__CUSTOM_DIVERGENCE_<GATE>: &str`).

**W44-194 (2026-05-22) shipped Phase 4** — two new CI gates protect this table from drift:

1. **`jxl-encoder/tests/divergence_table_drift.rs`** — for every gate's macro-emitted `divergence_row_ref`, asserts at least one stable anchor (W-code or fallback identifier) appears in THIS file. Catches the failure modes "added a gate to the macro without adding a row here", "renamed a gate's W-code without updating the row", "removed a gate without removing the row". Run via `cargo test -p jxl-encoder --features "__expert __internals" --test divergence_table_drift`.

2. **`jxl-encoder/tests/strategy_libjxl_byte_lock.rs`** — per-cell SHA256 byte lock for 10 synthetic fixtures encoded with `EncoderStrategy::Libjxl`. Catches the failure mode "edited a gate value (e.g. flipped `cfl_newton_libjxl_parity` to `false` under Libjxl) without intending the byte change". Per-cell drift report names the cell + expected SHA256 + observed SHA256 + byte sizes. Regen via `UPDATE_LIBJXL_BYTE_LOCK=1 cargo test --features __expert --test strategy_libjxl_byte_lock`.

This hand-maintained table remains canonical — the W44-194 drift test enforces FINDABILITY (the W-code referenced by the macro must appear in the table) rather than full auto-generation, because each chunk's lift gets its own rich-prose row that the macro's per-gate metadata cannot fully describe. A future build-script that auto-generates the table from richer per-chunk metadata is still a candidate; see W44-190 RFC §G5.

**Maintenance rule** (binding — see project CLAUDE.md): every PR/commit that touches any of:
- a gate condition (`effort >= N`, distance threshold, content discriminator)
- a numeric constant (entropy_mul, kFavor, threshold, multiplier)
- an algorithm choice (which TreeKind, which clustering strategy, which search policy)

MUST update this table. Adding a divergence: new row. Changing one: update existing row. Removing one (reaching libjxl parity): mark RESOLVED with commit SHA, do NOT delete.

**Status legend**:
- ACTIVE — divergence exists in current main, intentional or known-but-unfixed
- INTENTIONAL — divergence is deliberate (e.g. licensed product decision, perf tradeoff)
- KNOWN-BUG — divergence creates measurable RD/quality loss, awaiting fix
- RESOLVED — was divergent, now at libjxl parity (commit SHA recorded)
