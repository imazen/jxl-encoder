# The #110 byte regressions also occur in libjxl

The upstream bucket-matcher rewrite reproduces the terminal and path-lossless
size regressions on the exact derived-float inputs used in our archived screen.
Current upstream main retains these results. This is a compression-size finding,
not pixel corruption, a performance measurement, or proof that our port is exact.

## Controlled comparison

Three unmodified source snapshots, identical Release configuration and pinned
Brotli/Highway/skcms dependencies, on the ARM64 Mac:

- Parent: [`196a43d9`](https://github.com/libjxl/libjxl/commit/196a43d996aa6ed33ebf98812a7c6d43b2b6d01b).
- Rewrite: [`e8ff0976`](https://github.com/libjxl/libjxl/commit/e8ff09762481785938d8e4e01333ed3917571161).
- Current main: [`b8773895`](https://github.com/libjxl/libjxl/commit/b87738951c1254cd8cccaa6d47712ba735da56d8).

Four original sources, center crops at 64/256/259, lossless efforts 8/9,
one thread. RGB samples are exactly `f32((u16(sample) << 8) / 65535)` and
signaled as linear sRGB. Before encoding, every generated crop was checked
bit-for-bit against djxl's reconstruction of its retained Rust chain artifact.
PNG source hashes also match the September 24 screen. These are floats derived
from 8-bit images, not native HDR sources.

At the original failing 256x256 size, default grouping, bytes are:

| Image | Effort | Parent | Rewrite | Change |
|---|---:|---:|---:|---:|
| terminal | 8 | 32,910 | 43,195 | +31.25% |
| terminal | 9 | 31,691 | 42,869 | +35.27% |
| path-lossless | 8 | 325,061 | 334,587 | +2.93% |
| path-lossless | 9 | 316,240 | 316,198 | -0.013% |
| frymire | 8 | 86,079 | 82,154 | -4.56% |
| frymire | 9 | 65,451 | 65,087 | -0.56% |
| codec_wiki | 8 | 15,506 | 15,506 | 0% |
| codec_wiki | 9 | 15,390 | 15,390 | 0% |

The rewrite and current main are SHA256-identical on **all 32 cells**, including
the additional grouping check below. Terminal grows at every tested size and
both efforts. Frymire improves except at 64x64/e9 (+0.41%).

**Grouping matters.** Upstream automatically chooses 512-pixel groups for
259x259, so that default cell is still single-group. An additional eight cells
force `--modular_group_size 1` (256-pixel groups). The independent frame/TOC
parser confirms four groups in all 24 streams. Terminal still grows, but less:
32,831 to 33,992 (+3.54%) at e8 and 31,477 to 31,966 (+1.55%) at e9.
Path-lossless e8 grows 2.81%; frymire e8 shrinks 4.79%.

All **96 encoded outputs** reproduce every input float bit through both the
primary Rust decoder (`jxl 0.4.0`) and pinned djxl v0.12. PFM checks honor
endianness and bottom-up rows. This establishes the tested samples' losslessness;
it does not qualify the rewrite over a broader corpus.

## Reproduction and retained evidence

[`lz77_upstream_2026-09-27.tsv`](lz77_upstream_2026-09-27.tsv) contains every
cell, sizes, actual grouping, and source/input/three-output SHA256s.
[`lz77_upstream_2026-09-27.meta.json`](lz77_upstream_2026-09-27.meta.json)
binds source archives, dependencies, binaries, dynamic libraries, scripts and
verification logs. Every PFM, raw input, JXL and per-command log remains under
`~/tmp/jxl110-upstream-2026-09-27/`; original inputs remain under
`~/tmp/jxl-backlog/lz77-bucket-screen/`.

```
just lz77-upstream-build <new-artifact-root>
just lz77-upstream-compare <new-artifact-root> <retained-screen-root> <pinned-manifest>
```

The builder serializes builds with two workers under nice, uses immutable
upstream archives and never changes an existing reference checkout. The
comparison refuses existing output directories. The Rust verifier is an added
`--verify-manifest` mode on the existing `lossless_float_parity` example.
It checks artifact hashes, dimensions and every float's bits, and rejects an
empty manifest. No encoder defaults, matching algorithms or test expectations
changed. The production reference remains v0.12; newer revisions here are
explicit experimental comparison arms.

The broad Cargo example build filled the Mac's available disk while compiling
unrelated GPU development dependencies. Its log is retained. The final verifier
was instead compiled directly against existing Rust dependency artifacts; the
exact command is recorded in the metadata. The failed build's 464 encoder
incremental files were preserved on `dev` in
`~/tmp/jxl110-preservation-2026-09-27/mac-incremental.tar.gz`, with every file's
SHA256 checked against the original before removing its local uncompressed copy.
Workspace all-target Clippy subsequently passes against the pinned closure.
